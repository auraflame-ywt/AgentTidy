# AGENTS.md

Hybrid repo: Rust workspace + pnpm workspace. Phase 7 cleanup Beta implementation; cross-platform recovery and real-user acceptance remain pending. Full design doc: `Start.md` (Chinese) — code doc-comments reference it by section (e.g. §10, §18, §22).

## Commands

```bash
cargo fmt --all                                  # format (rustfmt, edition 2021)
cargo clippy --workspace --all-targets -- -D warnings   # CI treats warnings as errors
cargo test --workspace                            # all Rust tests
cargo test -p agenttidy-core                      # single crate
cargo run -p agenttidy-cli                         # run the CLI (bin name: agenttidy)
pnpm install                                      # frontend deps (pnpm@10, Node >= 20)
pnpm tauri dev                                    # desktop app (from repo root)
pnpm build:desktop                                 # tsc -b && vite build (this is the typecheck)
pnpm test:desktop                                  # pure frontend scenario regressions (Node runner)
```

CI (`.github/workflows/ci.yml`) runs fmt + clippy + test on **macOS and Windows**, and `pnpm build:desktop` + `pnpm test:desktop` on Linux. Run all three Rust checks locally before pushing; there is no separate frontend lint — `pnpm build:desktop` is the gate.

## Architecture (enforced red lines — see Start.md §22, ADR-0001)

- Layering: `crates/core` (domain) ← `crates/application` (single shared Application API) ← `crates/infrastructure`, `crates/provider-api` ← per-agent crates in `providers/` (workbuddy, claude-code, codex).
- `apps/cli` and `apps/desktop/src-tauri` are **thin shells** that forward to `agenttidy-application` — never add business logic there.
- Providers describe facts/operations only; cleanup policy lives in core. Providers never decide retention.
- Platform-specific code (macOS/Windows branches) is allowed **only** in `crates/infrastructure` and provider path discovery — never in business layers.
- No dynamic plugin system; provider registry is static.
- Default posture: read-only, trash-first, fail-closed. Unknown/Shared/Unsupported resources default to Blocked.

Domain and cleanup types are implemented after Phase 0 investigation (Start.md §19). Keep additions grounded in verified provider samples; do not model unsupported resource types ahead of investigation.

## Global constraints

- While in development, add appropriate comments to all new code to aid future understanding and maintenance. Follow the existing convention: module-level doc-comments explain purpose and reference design doc sections (`Start.md` §10, §18, §22); inline comments explain *why*, not *what*.

## Conventions & gotchas

- Workspace deps go through `[workspace.dependencies]` in root `Cargo.toml`; use `workspace = true` in member crates.
- `apps/desktop/src-tauri/gen/` is generated by Tauri and gitignored — don't edit or commit.
- LF line endings enforced via `.gitattributes` (matters for Windows commits).
- Changelog: `CHANGELOG.md`, Keep a Changelog format; update on notable changes.
- Fixtures (`fixtures/`) must be sanitized samples of real data — never hand-crafted; layout `fixtures/<provider>/<topic>/`. See `fixtures/README.md`.
- Any resource type with cleanup capability must get a doc in `docs/safety/` before its cleanup is enabled.
- Provider investigation docs live in `docs/providers/`; fill from real samples, not guesses.
